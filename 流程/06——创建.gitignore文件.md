# `.gitignore` 的作用是告诉 Git **哪些文件不要纳入版本控制**，
以保持仓库干净、轻量、跨平台可复现。

# 以下是之前的一些例子：

---

### 🧩 1. Python 临时文件

```bash
__pycache__/
*.pyc
*.pyo
*.pyd
*.so
```

Python 在运行时会自动生成缓存文件（例如 `.pyc`、`__pycache__`），
这些是**编译后的临时字节码文件**，不会影响功能，提交上 Git 只会让仓库臃肿。

---

### 🧩 2. 虚拟环境与备份

```bash
venv/
.venv/
env/
ENV/
venv_backup.tar.gz
```

这几项排除虚拟环境目录（`venv/`）和我们之前生成的备份文件，
因为这些文件在别人机器上没用、体积又大，GitHub 也不需要存。

---

### 🧩 3. ROS 2 构建产物

```bash
build/
install/
log/
```

ROS 2 在 `colcon build` 时会自动生成这三类目录（build/install/log）。
它们属于编译结果，不需要进版本库，否则仓库可能暴涨几百 MB。

---

### 🧩 4. Mujoco 临时文件

```bash
*.mjb
*.xml~
*.log
*.bak
```

仿真中 Mujoco 会生成模型缓存（`.mjb`）、编辑器临时文件（`.xml~`），
这些都是可再生文件。

---

### 🧩 5. VS Code 工作区文件

```bash
.vscode/
*.code-workspace
```

VS Code 的个人设置应只保留在你本地（例如主题、字体、插件），
不该进入版本控制，否则会污染别人的开发环境。

---

### 🧩 6. 模型、数据集、大文件

```bash
*.pth
*.onnx
*.zip
*.tar
*.tar.gz
*.h5
```

这是防止训练好的模型、压缩包、数据文件意外被提交。
这些应该放在单独的存储（如 release 或数据目录）里，不在 Git 中追踪。

---

### 🧩 7. 报告与缓存

```bash
reports/*.tmp
reports/__pycache__/
```

日志或临时报告文件可能在测试中自动生成，不具备长期价值。

---
